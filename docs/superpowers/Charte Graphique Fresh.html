01

Principes

Quatre règles simples qui définissent toute décision design.

Frais avant tout

Vert vif comme couleur primaire. Du blanc et du crème, jamais de noir lourd.

Avenant

Coins arrondis, ombres douces, mascotte présente. Jamais menaçant.

Clair en un coup d'œil

Couleur = info. Vert OK, jaune attention, orange urgent, rouge périmé.

Action évidente

Un seul CTA primaire par écran. Boutons pleins, pill, gros et verts.

Règles d'or

  • Tracking serré sur tous les titres (-0.02 à -0.04em). C'est ce qui rend Fresh "moderne".
  • Pas d'italiques, pas de soulignement. Surligneur vert pour emphase.
  • Chiffres en display : un nombre est aussi important qu'un titre. Toujours en gros et coloré.
  • Eyebrow avant les sections importantes — donne le contexte.

06

Mascotte — Aetchebibeast

Un petit chef monstre qui réagit à l'état du frigo. Toujours présent sur le hero et les états vides.
Heureux
Quand le frigo est en super forme (score ≥ 75). Hero dashboard, succès d'action.
Inquiet / dégoûté
Quand des aliments expirent ou que le score est bas. Banner alerte.
Rangement
Écran de scan/ajout, état "frigo vide", création d'un emplacement.
Action / mise à jour
Pendant un sync, une mise à jour, ou comme illustration de loading.
✓ À faire
Toujours sur fond clair (card ou bg). Drop-shadow douce. Taille minimum 76px, idéale 160-280px. Alignée à droite du contenu.
✗ À éviter
Ne jamais la rétrécir < 60px (perte de détail). Ne pas la mettre sur un fond coloré vif. Pas de rotation, pas de filtre, pas de teinte.

✓ Faire
• Toujours afficher l'image du produit si elle existe (scan, base, photo utilisateur).
• Crop carré cover, radius hérité du conteneur (12-18px).
• Si pas d'image : icône SVG de la catégorie, fond soft assorti.
• Si la catégorie est inconnue : icône générique neutre, fond card avec border dashed.
• Garder la même taille de slot (40-72px) qu'on ait l'image ou le fallback.
✗ Ne pas faire
• Pas d'emoji système pour représenter un aliment — c'était l'ancienne règle.
• Pas de fond plein de la couleur d'accent — toujours la version soft.
• Ne pas mélanger image et icône dans une même liste sans aligner les tailles.
• Pas d'icône colorée multi-tons : SVG line, un seul stroke.

Helper — score → couleur

// fresh-utils.ts
export function scoreFor(daysToExpire: number) {
  if (daysToExpire < 0)  return { color: "red",    label: "Expired" };
  if (daysToExpire <= 1) return { color: "red",    label: "Bad" };
  if (daysToExpire <= 3) return { color: "orange", label: "Use soon" };
  if (daysToExpire <= 7) return { color: "yellow", label: "Good" };
  return                       { color: "green",  label: "Excellent" };
}

09

Migrer ton app vers Fresh

Trois vagues pour adopter le système sans casser l'app existante.
Vague 1 · 1-2 jours

Tokens

Remplace seulement tes variables : couleurs, polices, radius, shadows, fond crème. L'app ressemble déjà à Fresh sans toucher aux composants.

  • Coller fresh-tokens.css
  • Charger DM Sans + Inter
  • Body bg → #f4e8c9
Vague 2 · 1-2 sem.

Patterns signature

Migre les éléments qui font vraiment Fresh. Refactor uniquement les écrans-clés (dashboard d'abord).

  • Score circulaire
  • Badges & pills colorés
  • Cards à fond pastel
  • Aetchebibeast en hero
  • Boutons pill, FAB vert
Vague 3 · continu

Détails & polish

Itère après mesure. Garde la mascotte cohérente, n'ajoute rien qui contredit les principes.

  • Emoji par catégorie
  • Micro-anims scan
  • États vides avec mascotte
  • Transitions douces (200ms)

Garde-fous

  • Feature-flag par écran pour pouvoir rollback rapidement.
  • Migre le dashboard d'abord, mesure (engagement, NPS), puis étends.
  • Garde tes composants form actuels au début. Fresh est avant tout un thème de présentation.
  • N'invente pas de couleur hors palette. Si un état nouveau arrive, demande-toi : est-ce green / yellow / orange / red / blue / pink / purple ?
10

Do / Don't

✓ Faire
• Une seule action primaire par écran (vert, pill, gros).
• Couleur = sémantique. Vert OK, jaune attention, orange urgent, rouge expiré.
• Pastilles soft pour les fonds d'icônes — jamais de remplissage plein.
• Mascotte sur le hero et les états vides.
• Chiffres en display 700, dans la couleur de leur statut.
✗ Ne pas faire
• Pas de gradients agressifs (sauf hero vert→deep).
• Pas de couleur primaire autre que le vert.
• Pas de border 1px partout — Fresh respire avec des fonds, pas des traits.
• Pas d'emoji en titre éditorial sérieux (réserver au contenu & CTA).
• Pas de mascotte à moins de 60px ni sur fond coloré vif.

✓ Faire — dark
• Surfaces neutres légèrement vertes-encre, jamais du noir pur (#000).
• Soft = teinte sombre opaque de la couleur d'accent (pas rgba) — meilleur contraste, pas de halo.
• Tous les accents montent en saturation/luminosité (green #2BB673 → #34C97F, orange #FF7A3A → #FF8A4F, red #EF4A5A → #FF6071, etc.).
• green-deep s'inverse : c'est plus clair que green (#5EE4A0) pour le texte sur green-soft.
• Ombres plus profondes (30-50% d'opacité) pour garder le relief.
• Mascotte sur fond card, jamais sur bg pur.
✗ Ne pas faire — dark
• Pas de #000 ni de gris-bleu froid (Material). Fresh reste chaud.
• Ne pas réutiliser les soft clairs (#D6F3E3) — illisibles sur dark.
• Pas d'ombre avec du flou exagéré : préfère opacité.
• Ne pas inverser le gradient hero (toujours green → green-deep).
• Pas de white pure sur les icônes — utilise ink crème.

Stratégie de bascule

  • Attribut sur <html> : data-theme="dark" ou "light". Aucun autre composant n'a à savoir.
  • Trois modes à exposer : Light · Dark · Auto (système). Persister la préférence en localStorage.
  • Transition douce : transition: background-color .25s, color .25s sur body et cards. Pas plus.
  • Tester chaque accent en dark : un orange #FF7A3A passe bien, mais le blue/pink/purple ont besoin d'un +lum pour atteindre WCAG AA.
